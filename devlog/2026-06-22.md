## 阶段 2 修复 3：多段线圆弧 bulge 支持 — 解决圆弧渲染为直线的问题

### 问题描述
导入 CAD 文件后，道路中线/边线中的圆弧段被渲染为直线（折线），视觉上呈现锯齿状。
用户在 CAD 中看到的圆弧在网页端变成了折线。

### 根因分析
DXF/DWG 中多段线（LWPOLYLINE/POLYLINE）的圆弧段通过 **bulge（凸度）** 表示：
- `bulge = tan(θ/4)`，其中 θ 是圆弧的总扫掠角
- bulge > 0：逆时针（圆心在弦左侧）
- bulge < 0：顺时针（圆心在弦右侧）
- bulge = 0：直线段

旧代码在两个层面丢弃了 bulge 信息：
1. **解析层**（`dxfParser.ts` / `dwgParser.ts`）：`ParsedEntity` 只存储 `vertices: {x, y}[]`，没有保留 bulge
2. **转换层**（`converter.ts`）：`buildCenterlinePath()` 对所有多段线顶点段都创建 `StraightPathSegment`

### 修复内容

#### 1. `src/core/dwg/types.ts` — ParsedEntity 新增 bulges 字段
```typescript
bulges?: number[];  // bulge[i] 对应 vertices[i]→vertices[i+1] 段
```

#### 2. `src/core/dwg/dxfParser.ts` — LWPOLYLINE/POLYLINE 解析时提取 bulge
- LWPOLYLINE: `pline.vertices.map(v => v.bulge ?? 0)`
- POLYLINE: 同上，顶点类型声明为 `{x, y, bulge}`

#### 3. `src/core/dwg/dwgParser.ts` — LWPOLYLINE/POLYLINE2D 解析时提取 bulge
- LWPOLYLINE: `pline.vertices.map(v => v.bulge ?? 0)`
- POLYLINE2D: 同上

#### 4. `src/core/geometry/path.ts` — 新增 `bulgeToArcSegment()` 函数
根据 bulge 值和弦端点计算圆弧参数：
- 半径公式：`r = chordLen × (1 + bulge²) / (4 × |bulge|)`
- 圆心偏移：`offset = chordLen × (1 - bulge²) / (4 × bulge)`（沿左法线方向）
- 圆心：`center = chordMidpoint + leftNormal × offset`
- 方向：`clockwise = bulge < 0`

#### 5. `src/core/dwg/converter.ts` — 多处更新
- `buildCenterlinePath()`：多段线顶点段根据 bulge 值创建 `ArcPathSegment`（bulge≠0）或 `StraightPathSegment`（bulge=0）
- 新增 `verticesToPolylineWithBulges()`：将带 bulge 的顶点列表高精度离散化为折线（用于边线渲染）
- `extractEdgePolyline()` / `separateEdgePolylines()`：改用 `verticesToPolylineWithBulges()`

## 阶段 2 修复 4：顺时针圆弧方向修正 — 解决边线圆弧渲染在反侧的问题

### 问题描述
用户反馈："右侧边线的圆变成另一半了"。右侧边线中的顺时针圆弧（bulge < 0）渲染时走了大圈（270° 逆时针），而非小弧（90° 顺时针），导致弧线出现在道路的另一侧。

### 根因分析
`bulgeToArcSegment()` 正确设置了 `clockwise = bulge < 0`，但下游的 `discretizeArcFromParams()` 函数始终按逆时针（角度递增、span 为正）离散化圆弧，忽略了 clockwise 标志。

例如：`startAngle = -π/2, endAngle = π, clockwise = true`
- 错误行为：span = π - (-π/2) = 3π/2 → 逆时针扫 270°（走了大圈）
- 正确行为：span 取负值 → 顺时针扫 -π/2（90° 小弧）

### 修复内容

#### `discretizeArcFromParams()` — 新增 `clockwise` 参数
```typescript
function discretizeArcFromParams(
  cx, cy, r, startAngle, endAngle, segmentsPerCircle,
  clockwise: boolean = false  // 新增
): Point2D[] {
  let span = endAngle - startAngle;
  if (clockwise) {
    if (span > 0) span -= 2 * Math.PI;  // 顺时针：确保 span 为负
  } else {
    if (span < 0) span += 2 * Math.PI;  // 逆时针：确保 span 为正
  }
  // step = span / segments，span 的符号决定离散化方向
}
```

#### `verticesToPolylineWithBulges()` — 传递 clockwise 参数
```typescript
discretizeArcFromParams(cx, cy, r, startAngle, endAngle, segmentsPerCircle, arc.clockwise)
```

## 阶段 4 修复：线宽与比例调整 + 直弧交接转向 (2026-06-22)

### 问题 1：线太粗，道路叠在一起

**根因**：风电场道路仅 6m 宽，初始全图缩放时 3 条线（中线+左右边线）的 strokeWidth 在像素层面叠加，无法区分。

**修复**（`src/components/road/RoadCanvas.tsx`）：
- 所有 Line 组件添加 `strokeScaleEnabled={false}`，线宽保持恒定屏幕像素，不随缩放变化（CAD 查看器标准做法）
- 全面减小 strokeWidth：网格 0.5→0.3、边线 1.5→1、中线 2→1.5、包络 2→1、冲突 X 2.5→1.5、冲突高亮 3→2、车辆 2→1

### 问题 2：直线接圆曲线交接处转弯不过来

**根因**：风电场道路没有缓和曲线，直线直接接圆曲线。当前模拟引擎按路径切线计算车辆航向，在曲率突变处车辆物理上需要"停车→打方向盘→再起步"，但引擎未体现此过程。

**修复**（`src/core/simulation/engine.ts`）：
- 新增 `segmentLength()` 辅助函数：计算单段路径长度
- 新增 `segmentStartStation()` 辅助函数：计算段起点累计里程
- 模拟主循环新增段切换检测逻辑：
  - 跟踪 `prevSegmentIndex`，检测段类型变化（straight↔arc）
  - 在交接点处插入转向过渡步骤：车辆停在交接点，航向切换为新段切线方向
  - 过渡步骤的角点加入凸包计算，反映车辆打方向盘后的姿态
  - 同时支持正向/反向行驶（forward/reverse）

### 技术要点

| 概念 | 说明 |
|------|------|
| strokeScaleEnabled=false | 线宽恒定屏幕像素，CAD 查看器标准做法 |
| 转向过渡步骤 | 段类型切换时在交界点插入额外 SimulationStep |
| 交界点定位 | segmentStartStation(newSegmentIndex) 精确确定交接里程 |
| 新段航向查询 | junctionStation + 0.001m 微偏移确保取到新段 heading |

## 阶段 4 修复 2：反向行驶 + 段缓存修复 (2026-06-22)

### 问题描述
用户反馈模拟时车辆在圆弧段不转弯，仍然沿直线行驶。经过深入排查，发现两个关键 bug。

### Bug 1：`pointOnPathInfo` 段索引缓存在反向行驶时失效

**根因**：段索引缓存（`lastSegmentIndex`）假设 station 单调递增，但反向行驶时 station 单调递减。
当 station 退到缓存段之前时，`accumulated + segLength >= station` 恒为真（大量程 ≥ 小 station），
导致 `remaining = station - accumulated` 为负值，`pointOnSegment` 返回错误的坐标和航向。

**修复**（`src/core/geometry/path.ts`）：
- 在计算 `accumulated`（缓存段之前的累计里程）后新增反向检测：
  `if (accumulated > station) { startIdx = 0; accumulated = 0; }`
- 当 station 已退到缓存段之前，自动重置为从头搜索，确保正确查找。

### Bug 2：反向行驶时交接点定位公式错误

**根因**：原代码用 `segmentStartStation(centerline, info.segmentIndex)` 定位交接点，
正向行驶时正确（新段起点 = 交接点），但反向行驶时错误（新段在路径几何上靠前，
其起点 != 交接点）。同时 `totalLen - junctionStation - 0.001` 的查詢公式
在反向时将 station 映射到完全错误的位置。

**修复**（`src/core/simulation/engine.ts`）：
- 交接段索引改为 `Math.max(prevSegmentIndex, info.segmentIndex)`，正向/反向均正确定位交接点
- 反向交接查詢改为 `junctionStation - 0.001`（而非错误的 `totalLen - junctionStation - 0.001`）
- 反向查詢缓存使用 `info.segmentIndex`（新进入的段），正向使用 `prevSegmentIndex`
- 补充 `PathSegment` 类型导入

### 技术要点

| 概念 | 说明 |
|------|------|
| 反向缓存失效 | station 递减时 accumulated > station → 缓存段已超前，需重置 |
| 交接段索引 | `max(prevIdx, infoIdx)` 统一正向/反向的交接点定位 |
| 反向交接查詢 | `junctionStation - 0.001` 正确回退到路径几何前段（行驶方向新段） |
