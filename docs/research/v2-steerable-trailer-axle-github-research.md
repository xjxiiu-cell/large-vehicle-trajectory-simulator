# V2 铰接车：可转向挂车轴 GitHub 源码调研

调研日期：2026-09-17  
范围：前轮转向牵引车 + 单半挂车、低速（当前产品默认 5 km/h）、只前进。本文是实现前的技术调研，不是工程设计结论，也不直接引入第三方代码。

## 结论先行

**知道，而且这不是一个可以用“挂车后轮可转向”一个勾选项概括的功能。** 半挂车后部轴组的转向，至少有三类在运动学上不同的系统：

| 类型 | 转向角从哪里来 | 对模拟器的含义 |
| --- | --- | --- |
| 固定轴组 | `δt = 0` | V2 基础半挂车模型；挂车内轮差最大。 |
| 被动自转向 / 随动转向 | 机械随动、转盘或拖曳/回正机构决定；常与铰接角、行驶方向、速度、锁止状态有关 | **仅靠车长、轴距和“最大角度”不能唯一算出**；还须有厂家转向曲线或可标定的机械参数/经验规律。 |
| 强制（主动）转向 | 液压、电控或独立操作者给出目标角度，可能按铰接角/牵引车转向角联动 | 挂车轴转角是额外控制量，必须有最大角、角速度、联动规律或外部指令。 |

GitHub 中确有“牵引车 + 可转向挂车”源码，但本次没有找到一个同时满足“成熟、开源许可明确、低速单半挂车、后部多轴组转向、双车身碰撞与 Hybrid A*”的可直接复用项目。最直接的运动学源码是一个小型、**未标明许可证**的 Matlab 项目；可作公式交叉核验，不能复制。成熟 MIT 拖挂 Hybrid A* 项目仅覆盖**固定挂车轴**，适合作为 V2 基础与碰撞/规划框架参考。

因此建议：**V2 第一轮仍先交付固定挂车轴的连续模型；把“转向挂车轴”预留在参数和状态接口中，但不默认启用。** 等用户提供实际车型的转向类别和数据后，单列一个已验证的小阶段。否则软件会以看似精确的曲线，输出没有机械依据的扫掠宽度，工程风险比“不支持”更高。

## 为什么“可转向”会改变模型

沿 V2 基础模型的记号：

```text
前进方向 →
牵引车前转向轴 ─ L ─ 牵引车后轴 R ─ a ─ 铰接点 H ─ b ─ 挂车等效轴组中心 T
```

- `θ`：牵引车朝向；`ψ`：挂车车身朝向；`α = wrap(θ - ψ)`：铰接角。
- `δf`：牵引车前轮等效转角；`δt`：挂车**等效可转向轴组**相对挂车车身的转角。
- `a`：牵引车后轴至铰接点的有符号距离（第五轮在后轴后方时 `a < 0`）；`b > 0`：铰接点至挂车等效轴组中心的距离。
- `R` 是内部积分参考，`H = R + a·e(θ)`，`T = H - b·e(ψ)` 每帧由约束重新构造。`T` 不能独立累积，否则会产生挂车漂移。

牵引车以 `v > 0` 前进，`κ = tan(δf) / L`，则：

```text
Ṙ = v · e(θ)
θ̇ = v · κ
Ḣ = Ṙ + a · θ̇ · n(θ)

ψ̇ = [ n(ψ)·Ḣ - tan(δt) · e(ψ)·Ḣ ] / b
```

其中 `e(φ) = (cos φ, sin φ)`，`n(φ) = (-sin φ, cos φ)`。当 `δt = 0`，最后一式正好退化为 V2 固定挂车轴方程；当 `δt ≠ 0`，挂车转角会直接改变挂车朝向变化率及扫掠宽度。`Tractor-Trailer-Control` 把第二转角 `delta2` 放入状态和控制，正是这一类“主动转向”的最小结构。[源码](https://github.com/maxruizluyten/Tractor-Trailer-Control/blob/master/main.m)

### 被动自转向不是少一个输入，而是缺少一条物理规律

“被动”只说明没有由本软件直接下发的执行器指令，并不自动给出 `δt`。例如：

- 铰接角机械联动：可由经标定的 `δtTarget = f(α)` 给出；
- 牵引车转向机械联动：可由 `δtTarget = f(δf, α)` 给出；
- 自由随动/回正机构：需至少有转向轴的拖曳距、回正力/阻尼、摩擦、限位或经实测的动态转向曲线；
- 低速锁止或倒车锁止：需有锁止条件，尽管当前 V2 只做前进，仍要知道直行是否回正和转弯是否存在死区。

若这些信息不存在，纯运动学不能唯一确定 `δt(t)`；任意猜一个“随铰接角比例”的关系都会改变内轮差和道路净距。该不确定性不能用更密的积分步长解决。

### 多轴组也不能被不加说明地压缩成一个点

对常见挂车后部多轴组，V2 首轮可把**固定且平行**轴组近似为一个“等效轴组中心”，用于车身姿态和扫掠边界。但多根固定轴在曲线中本就存在轮胎擦滑；若其中只有一根或多根可转向，必须额外说明：

1. 每根轴相对铰接点的位置；
2. 哪些轴转向、是否同相/反相、是否共用机械连杆；
3. 各轴最大转角、最大转向角变化率、左右轮 Ackermann 关系或厂家等效规律；
4. 是否按速度、载荷、行驶方向或铰接角锁止/限位。

在未取得这些数据时，可把车身扫掠当作几何近似，但不能声称轮胎轨迹或轮胎磨耗结论可靠。

## 建议的数据模型与界面

用户说“像刚性车一样输入相关信息”是正确的产品方向；但新增项必须反映真实机构，而非只填车长宽。建议在挂车参数中提供以下结构，默认安全地设为固定：

```ts
type TrailerAxleSteeringMode =
  | 'fixed'
  | 'passive_linked'
  | 'active_linked'
  | 'active_commanded';

interface TrailerSteeringParams {
  mode: TrailerAxleSteeringMode;
  equivalentAxleGroupCenterFromHitchM: number;
  maxSteeringAngleDeg?: number;
  maxSteeringRateDegPerSec?: number;
  // passive_linked / active_linked 必填：厂家曲线或经实测标定的规律
  steeringLaw?: {
    articulationGain?: number;
    tractorSteeringGain?: number;
    deadbandDeg?: number;
    centerReturnRateDegPerSec?: number;
  };
  // 多轴组的工程描述；第一轮可只存档，不把它伪装成完整轮胎动力学
  axleRows?: Array<{ offsetFromHitchM: number; steerable: boolean }>;
}
```

- `fixed`：不出现挂车转向控制，`δt=0`。
- `passive_linked`：`δt` 是有角速度、死区和回正过程的状态；目标角只能来自已知/标定规律，不能让规划器自由选择。
- `active_linked`：仍按厂家给定联动规律驱动，只是其执行器可控；用于现实中由 ECU 随牵引车输入联动的类型。
- `active_commanded`：规划器可选择 `δtTarget`，但搜索维度和验证责任显著增加，必须先有车型的角度/速率/锁止数据。

界面第一屏应先问“固定 / 被动随动 / 主动联动 / 独立控制”，随后仅显示该类型需要的参数。不能把不具备转向规律的“可转向”车辆按固定轴或按任意比例自动处理而不提示。

## 对路径规划、碰撞和扫掠的影响

1. **连续积分**：无论类型如何，都使用当前项目已有的 `ds ≤ 0.1m` 后轴步进，牵引车、铰接点、挂车都从同一个连续状态序列生成。主动/被动挂车转角同样要受角速度限制，不能在回放帧之间突变。
2. **状态**：固定轴最低状态为 `(R.x, R.y, θ, ψ, δf)`；带可转向轴至少加 `δt`。若挂车转向有一阶执行器或回正逻辑，`δt` 是必须保存和去重的状态，不能每帧瞬时重算。
3. **碰撞**：牵引车和挂车车身矩形仍分别做道路走廊、安全净距、相邻状态扫掠检查。轮胎转角改变的是后续车身位姿，不把车身安全校验替换成“轴线是否在路内”。
4. **规划器**：
   - `passive_linked` / `active_linked`：转向规律确定时，规划器只选 `δfTarget`；每个原语内联动更新 `δt`，搜索维度可控。
   - `active_commanded`：原语必须同时枚举 `δfTarget` 与 `δtTarget`；不要直接从 9 档变成 9×9。先限制为经验证的耦合控制律或少量相位关系，再考虑独立控制。
5. **结果说明**：结果须标明“固定轴几何模拟”“按厂家/实测随动规律的几何模拟”或“主动转向控制假设”。没有标定规律时，应显示“转向机构数据缺失”，而不是输出通过/不通过。

## 建议的分阶段实施（每阶段停止测试）

### V2-1：固定挂车轴连续模型与车型参数（先做）

- 完成牵引车 + 单半挂车的连续积分、铰接点约束、牵引车前轴/后轴/挂车等效轴组轨迹、铰接角、牵引车/挂车轮廓。
- 参数界面新增“挂车轴组转向类型”，默认 `fixed`；先把非固定类型标为“需要车型转向数据，暂不可模拟”，避免错误承诺。
- 自动化测试：直线、恒定转向圆弧、铰接约束、相邻帧连续、固定轴退化关系。
- **停止，由用户在直线、左弯、右弯图纸回放确认。**

### V2-1A：可转向挂车轴的单独验证阶段（仅有车型数据后）

- 先只支持**一个等效可转向轴组**，不做多轴独立 Ackermann。
- 被动/主动联动：录入厂家曲线或用户提供的标定点，补齐最大角、角速度、死区/回正/锁止条件；对比实车转弯或厂家扫掠图。
- 主动独立控制：先实现手工/固定规律回放验证；不立即接入自动规划。
- **停止，由用户确认该车型的挂车轴方向、回正与扫掠趋势。**

### V2-2：双车身安全走廊、冲突与双段扫掠

- 在 V2-1（及适用时 V2-1A）通过后，纳入牵引车、挂车双车身完整安全校验、最小净距、冲突归属和连续扫掠。
- **停止，由用户以实际图纸和不同安全净距验收。**

### V2-3：铰接车自动安全路线

- 固定轴或转向规律确定的车型，才进入 Hybrid A*。挂车实际转角和铰接角纳入状态/去重，继续使用 Worker、进度和取消。
- **停止，由用户验证提前转向、内轮差和无解时最远连续可执行轨迹。**

### V2-4：真实图纸回归与交付

- 使用真实 DXF/DWG 和实际车型尺寸；转向挂车轴必须与厂家扫掠模板或实测轨迹交叉核验。
- 在校核前，页面始终标示“几何模拟结果，不作为最终工程设计结论”。

## 开始开发前必须补齐的车型事实

用户已确认“前轮转向牵引车 + 单半挂车、只前进”。针对可转向挂车轴，还需要实际车型资料：

1. 后部轴组是固定、被动随动、液压/电控主动联动，还是由人员独立操纵？
2. 可转向的是哪一根/哪几根轴；每根轴相对第五轮的距离、轴间距及等效轴组中心。
3. 最大转角、最大转向速度；直行回正、倒车/低速锁止（即使当前只前进，也会影响初始与退出弯道）。
4. 被动/联动型的厂家 `δt–α` 或 `δt–δf` 曲线、说明书，或至少可用于标定的一次实测转弯轨迹。
5. 牵引车后轴到第五轮、第五轮到挂车轴组、两段车体前后悬、宽度。全部以米录入，继续沿用 V1 的单位规则。

没有第 1–4 项时，正确做法是先按固定轴 V2-1 模拟，并在界面明确提示“可转向挂车轴尚未按该车型机构标定”。
